📅 Morning — Routing, Layouts & Server Architecture

1. App Router & Structural Pages

Next.js uses a file-system based App Router where directories define url paths. A page.js file makes a route accessible, while a layout.js serves as a wrapper to persist UI states across navigation events.

// app/dashboard/layout.js
export default function DashboardLayout({ children }) {
  return (
    <section>
      <nav>Dashboard Header</nav>
      {children} /* Injects active page structure sub-nodes */
    </section>
  );
}

// app/dashboard/page.js (Mapped straight to /dashboard URL)
export default function DashboardPage() {
  return <h1>Welcome to the Dashboard, Venudhar!</h1>;
}

2. React Server Components (RSC) vs Client Components

By default, Next.js components are Server Components. They execute solely on the server host to reduce javascript payloads. To introduce reactivity hooks (like useState or useEffect), you explicitly label the file with the 'use client' directive.

// app/components/ServerComponent.js (Default)
export default function ServerComp() {
  console.log("I only execute on the secure back-end terminal!");
  return <p>Static Server Data View</p>;
}

// app/components/ClientComponent.js
'use client'; // Enables client bundle compilation hydration hooks

import { useState } from 'react';

export default function ClientComp() {
  const [isOpen, setIsOpen] = useState(false);
  return <button onClick={() => setIsOpen(!isOpen)}>Toggle Menu</button>;
}

3. Link & Programmatic Navigation

Next.js optimizes transitions with the <Link> component, performing viewport background prefetching. For programmatic shifts inside events, use the useRouter hook.

import Link from 'next/link';
import { useRouter } from 'next/navigation';

export default function NavigationExample() {
  const router = useRouter();

  return (
    <div>
      <Link href="/portfolio">Go to Portfolio View</Link>
      <button onClick={() => router.push('/settings')}>Settings</button>
    </div>
  );
}

4. Server-Side Data Fetching

Because Server Components are asynchronous by design, you can directly fetch data asynchronously inside the function body using standard await expressions, avoiding localized state hooks entirely.

// Fetching data directly on the server layer before UI compilation
async function getPortfolioData() {
  const res = await fetch('https://api.example.com/stocks');
  if (!res.ok) throw new Error('Failed to retrieve dataset');
  return res.json();
}

export default async function StocksPage() {
  const stocks = await getPortfolioData();

  return (
    <ul>
      {stocks.map((stock) => <li key={stock.id}>{stock.symbol} — {stock.price}</li>)}
    </ul>
  );
}

📅 Afternoon — Data Pipelines, Caching & Action Handlers

5. Dynamic Routes (Dynamic Path Tokens)

To match dynamic slugs (like /stock/ONGC), bracket folder layouts ([slug]) isolate tokens natively inside page parameters.

// app/stock/[symbol]/page.js
// Mapped implicitly when users access /stock/ONGC or /stock/RELIANCE
export default async function StockDetailsPage({ params }) {
  const { symbol } = await params; // Extract dynamic structural parameters safely
  
  return <h1>Viewing stock ticker data for: {symbol}</h1>;
}

6. Data Caching & Incremental Revalidation

Next.js intercepts native fetch operations to store data copies. You can control data persistence statically or trigger periodic cache updates using Incremental Static Regeneration (ISR).

// Force the server cache configuration to revalidate structural snapshots every 60 seconds
async function getRevalidatedData() {
  const res = await fetch('https://api.example.com/market', {
    next: { revalidate: 60 } // Cache lifetime indicator parameter
  });
  return res.json();
}

7. Route Handlers (Back-End API endpoints)

Next.js handles API development directly using route.js files inside your app directory, executing safely as independent back-end endpoints.

// app/api/portfolio/route.js
import { NextResponse } from 'next/server';

export async function GET() {
  const mockData = [{ id: 1, symbol: 'ONGC', price: 270 }];
  return NextResponse.json(mockData);
}

8. Server Actions (Seamless Form Submissions)

Server Actions let you securely invoke server side logic directly through form submission triggers without building manual API endpoints.

// app/portfolio/NewStockForm.js
export default function NewStockForm() {
  // Server Action executing directly on the back-end host
  async function handleFormSubmit(formData) {
    'use server'; // Direct directive tags system execution boundary
    const ticker = formData.get('tickerSymbol');
    console.log(`Saving ${ticker} securely to database...`);
  }

  return (
    <form action={handleFormSubmit}>
      <input name="tickerSymbol" type="text" />
      <button type="submit">Add Stock entry</button>
    </form>
  );
}

10. Image Component Optimization

The specialized Next.js <Image> element automatically compresses images, generates responsive layouts, and uses lazy loading to minimize core web vitals load times.

import Image from 'next/image';
import profilePic from '../public/profile.png';

export default function ProfileView() {
  return (
    <Image
      src={profilePic}
      alt="User Profile Avatar"
      placeholder="blur" // Smooth automatic blur loaders
    />
  );
}

11. Edge Middleware Systems (Global Auth Guards)

Middleware files run just before requests finish loading, making them perfect for handling catch-all authorization guards, session checks, or routing updates.

// middleware.js (Placed uniquely at root app tree context level)
import { NextResponse } from 'next/server';

export function middleware(request) {
  const hasToken = request.cookies.has('session_token');
  if (!hasToken) {
    // Direct unauthenticated users safely back toward baseline index home
    return NextResponse.redirect(new URL('/', request.url));
  }
}

export const config = {
  matcher: '/dashboard/:path*', // Guard target paths recursively
};
