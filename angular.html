📅 Day 1 — Core Angular Fundamentals

1. Components & TypeScript Templates

Angular components use a @Component decorator to bind a TypeScript class to an HTML template. Instead of JSX, Angular uses standard HTML extended with its own template expression syntax.

import { Component } from '@angular/core';

@Component({
  selector: 'app-welcome',
  template: '<h1>Hello, Venudhar</h1>'
})
export class WelcomeComponent {}

// Component with template expressions
@Component({
  selector: 'app-greeting',
  template: '<h2>Welcome back, {{ name }}!</h2>'
})
export class GreetingComponent {
  name = 'Venudhar';
}

2. Input & Output Properties (Props Equivalent)

Data flows down into components via @Input() properties. Data flows up to parent components by emitting events using @Output() and an EventEmitter.

import { Component, Input, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-user-card',
  template: `
    <div>
      <p>{{ name }}</p>
      <p>{{ role }}</p>
      <button (click)="notifyParent()">Click Me</button>
    </div>
  `
})
export class UserCardComponent {
  @Input() name!: string;
  @Input() role!: string;
  @Output() statusChange = new EventEmitter<string>();

  notifyParent() {
    this.statusChange.emit('Card Clicked!');
  }
}

// Usage in parent: <app-user-card [name]="'Venudhar'" [role]="'Tech Lead'" (statusChange)="onStatus($event)"></app-user-card>

3. Component State & Change Detection

In Angular, any public property on the class acts as component state. You don't need a state hook; updating the class property directly triggers Angular's change detection to update the DOM.

import { Component } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <button (click)="increment()">
      Count: {{ count }}
    </button>
  `
})
export class CounterComponent {
  count = 0;

  increment() {
    this.count++;
  }
}

4. Event & Binding Handling

Angular separates data flow syntactically: brackets [] are used for property binding (data into the DOM), and parentheses () are used for event binding (data out of the DOM).

@Component({
  selector: 'app-search-box',
  template: '<input (input)="handleInput($event)" placeholder="Search..." />'
})
export class SearchBoxComponent {
  handleInput(event: Event) {
    const value = (event.target as HTMLInputElement).value;
    console.log(value);
  }
}

5. Control Flow (Conditional Rendering)

Angular features a built-in block syntax (@if / @else) to conditionally render fragments of HTML directly within your templates.

@Component({
  selector: 'app-status',
  template: `
    <div>
      @if (isLoggedIn) {
        <p>Welcome back!</p>
      } @else {
        <p>Please log in.</p>
      }
    </div>
  `
})
export class StatusComponent {
  isLoggedIn = true;
}

6. Tracked Lists (@for Blocks)

To render lists, Angular uses the @for block. A track expression is required, serving the same optimization purpose as React's unique key prop.

interface Stock { id: number; symbol: string; price: number; }

@Component({
  selector: 'app-stock-list',
  template: `
    <ul>
      @for (stock of stocks; track stock.id) {
        <li>{{ stock.symbol }} — {{ stock.price }}</li>
      }
    </ul>
  `
})
export class StockListComponent {
  stocks: Stock[] = [{ id: 1, symbol: 'ONGC', price: 270 }];
}

7. Forms (Reactive Forms)

For robust state management, Angular offers Reactive Forms. You create a FormControl explicitly in your TypeScript file and tie it directly to the template input.

import { Component } from '@angular/core';
import { FormControl, ReactiveFormsModule } from '@angular/forms';

@Component({
  selector: 'app-login-form',
  imports: [ ReactiveFormsModule ],
  template: `
    <form (ngSubmit)="handleSubmit()">
      <input [formControl]="emailControl" />
      <button type="submit">Submit</button>
    </form>
  `
})
export class LoginFormComponent {
  emailControl = new FormControl('');

  handleSubmit() {
    console.log(this.emailControl.value);
  }
}

📅 Day 2 — Core Lifecycle & Architecture

1. Component Lifecycle Hooks (ngOnInit & ngOnDestroy)

Instead of useEffect, Angular utilizes explicit lifecycle interfaces. ngOnInit handles initialization tasks, while ngOnDestroy acts as the execution cleanup mechanism.

import { Component, OnInit, OnDestroy, Input } from '@angular/core';

@Component({
  selector: 'app-stock-price',
  template: '<p>{{ symbol }}: {{ price }}</p>'
})
export class StockPriceComponent implements OnInit, OnDestroy {
  @Input() symbol!: string;
  price: number | null = null;

  ngOnInit() {
    // Component initialized. Fetch data here.
  }

  ngOnDestroy() {
    // Cleanup tasks (like unsubscribing from timers or streams)
  }
}

2. Dependency Injection & Services

Instead of Context Providers, Angular uses Dependency Injection (DI). Services hold shared logic or values and can be cleanly injected straight into a component's constructor.

import { Injectable, Component } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class ThemeService {
  theme = 'dark';
}

@Component({
  selector: 'app-toolbar',
  template: '<div [class]="themeService.theme">Toolbar</div>'
})
export class ToolbarComponent {
  constructor(public themeService: ThemeService) {}
}

3. DOM Access with @ViewChild

To get direct reference to a DOM element or a child component without managing state, use the @ViewChild decorator coupled with an ElementRef wrapper.

import { Component, ViewChild, ElementRef, AfterViewInit } from '@angular/core';

@Component({
  selector: 'app-focus-input',
  template: '<input #myInput />'
})
export class FocusInputComponent implements AfterViewInit {
  @ViewChild('myInput') inputRef!: ElementRef<HTMLInputElement>;

  ngAfterViewInit() {
    this.inputRef.nativeElement.focus();
  }
}

4. Pipes for Data Transformation

Pipes are utility operations used to transform visible data directly within your markup layouts, acting as a clean alternative to inline logic changes.

import { Component } from '@angular/core';
import { CurrencyPipe, UpperCasePipe } from '@angular/common';

@Component({
  selector: 'app-format',
  imports: [ CurrencyPipe, UpperCasePipe ],
  template: `
    <p>Company: {{ company | uppercase }}</p>
    <p>Price: {{ price | currency:'INR' }}</p>
  `
})
export class FormatComponent {
  company = 'ongc';
  price = 270.45;
}

5. Custom Directives

Directives allow you to extend HTML elements with custom behaviors. While components are structurally directives with templates, attribute directives manipulate structural elements directly.

import { Directive, ElementRef, HostListener } from '@angular/core';

@Directive({ selector: '[appHighlight]', standalone: true })
export class HighlightDirective {
  constructor(private el: ElementRef) {}

  @HostListener('mouseenter') onMouseEnter() {
    this.el.nativeElement.style.backgroundColor = 'yellow';
  }
  @HostListener('mouseleave') onMouseLeave() {
    this.el.nativeElement.style.backgroundColor = null;
  }
}

6. Reactive Programming with RxJS

Angular deeply integrates RxJS and Observables to manage streams of asynchronous data. Think of it as a clean engine that handles data state changes smoothly over time.

import { Component, OnInit } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

@Component({
  selector: 'app-reactive',
  template: '<p>Active Users: {{ userCount$ | async }}</p>'
})
export class ReactiveComponent implements OnInit {
  userCount$ = new BehaviorSubject<number>(0);

  ngOnInit() {
    this.userCount$.next(10); // Emit updated stream parameters
  }
}

7. Content Projection (ng-content)

Angular handles component composition via Content Projection. The <ng-content> tag acts as a placeholder that injects whatever markup the parent nests inside its tags.

@Component({
  selector: 'app-card',
  template: `
    <div class="card">
      <ng-content></ng-content>
    </div>
  `
})
export class CardComponent {}

// Usage: <app-card><h3>ONGC</h3></app-card>

📅 Day 3 — Real-World Angular Architecture

1. Angular Router (Navigation)

Angular includes a full-featured routing engine out of the box. Paths map directly to your components, and specialized directives handle client-side routing updates smoothly.

import { Routes, RouterLink, RouterOutlet } from '@angular/router';

export const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'portfolio', component: PortfolioComponent }
];

@Component({
  selector: 'app-root',
  imports: [ RouterLink, RouterOutlet ],
  template: `
    <nav>
      <a routerLink="/">Home</a>
      <a routerLink="/portfolio">Portfolio</a>
    </nav>
    <router-outlet></router-outlet>
  `
})
export class AppComponent {}

2. HTTP Client (API Data Layer)

Angular features an optimized HTTP service engine (HttpClient) that handles requests natively via RxJS streams, avoiding manual promise chains.

import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class PortfolioService {
  private http = inject(HttpClient);

  getStocks(): Observable<any[]> {
    return this.http.get<any[]>('/api/portfolio');
  }
}

3. Global State Management (Signals)

Angular Signals provide fine-grained reactivity built right into the core framework, tracking and informing individual template nodes without demanding heavy, external global stores.

import { Injectable, signal, computed } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class PortfolioStore {
  stocks = signal<{ id: number; symbol: string }[]>([]);
  totalCount = computed(() => this.stocks().length);

  addStock(symbol: string) {
    this.stocks.update(current => [...current, { id: Date.now(), symbol }]);
  }
}

4. Global Error Handling (ErrorHandler)

Instead of localized boundary wrappers, Angular handles core runtime failures globally by extending and overriding its default ErrorHandler provider class.

import { ErrorHandler, Injectable } from '@angular/core';

@Injectable()
export class GlobalErrorHandler implements ErrorHandler {
  handleError(error: any): void {
    console.error('An error occurred globally:', error.message);
  }
}
// Registered via: { provide: ErrorHandler, useClass: GlobalErrorHandler }

5. Component Testing (TestBed)

Angular comes packaged with comprehensive test suites. The TestBed utility simplifies mock behaviors, click triggers, and UI assertions.

import { TestBed, ComponentFixture } from '@angular/core/testing';
import { CounterComponent } from './counter.component';

describe('CounterComponent', () => {
  let fixture: ComponentFixture<CounterComponent>;

  beforeEach(() => {
    TestBed.configureTestingModule({ imports: [ CounterComponent ] });
    fixture = TestBed.createComponent(CounterComponent);
    fixture.detectChanges();
  });

  it('should increment count on click', () => {
    const button = fixture.nativeElement.querySelector('button');
    button.click();
    fixture.detectChanges();
    expect(button.textContent).toContain('Count: 1');
  });
});

6. Angular SSR & Hydration (Server Rendering)

Angular features native Server-Side Rendering (SSR). Components are compiled into structural HTML server-side before instantly hydrating into a fast client application.

// App setup automatically provisions server bootstrap steps:
import { bootstrapApplication } from '@angular/platform-browser';
import { config } from './app.config.server'; // includes provideServerRendering()
import { AppComponent } from './app.component';

const bootstrap = () => bootstrapApplication(AppComponent, config);
export default bootstrap;

7. Performance & Optimization (Deferrable Views)

Deferrable Views (@defer) allow you to lazy-load massive components or layout nodes automatically only when specific triggers (like viewport visibility) are fulfilled.

@Component({
  selector: 'app-dashboard',
  template: `
    @defer (on viewport) {
      <app-heavy-charts />
    } @placeholder {
      <div>Charts will load when scrolled into view...</div>
    }
  `
})
export class DashboardComponent {}
