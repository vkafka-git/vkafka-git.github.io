⚛️ React 3‑Day Crash Guide

📅 Day 1 — Core React Fundamentals

1. JSX & Components

JSX lets you write HTML-like markup directly inside JavaScript. A component is just a function that returns JSX — it's the basic building block of every React app.

function Welcome() {
  return <h1>Hello, Venudhar</h1>;
}

// Functional component with JSX expressions
const Greeting = ({ name }) => {
  return <h2>Welcome back, {name}!</h2>;
};

2. Props

Props are how a parent component passes data into a child component — similar to method parameters in C#. They're read-only inside the child.

function UserCard({ name, role }) {
  return (
    <div>
      <p>{name}</p>
      <p>{role}</p>
    </div>
  );
}

// Usage
<UserCard name="Venudhar" role="Tech Lead" />

3. State with useState

State is data that belongs to a component and can change over time. useState gives you a value plus a setter function — updating the value triggers a re-render.

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}

4. Event Handling

React wraps native DOM events in its own synthetic event system, but the syntax stays close to plain JS — you pass a function reference, not a string.

function SearchBox() {
  const handleChange = (e) => {
    console.log(e.target.value);
  };
  return <input onChange={handleChange} placeholder="Search..." />;
}

5. Conditional Rendering

There's no special syntax for "if" in JSX — you use regular JavaScript expressions like ternaries or && to decide what gets rendered.

function Status({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? <p>Welcome back!</p> : <p>Please log in.</p>}
    </div>
  );
}

6. Lists & Keys

Use .map() to render arrays of data as elements. Each item needs a stable, unique key so React can track changes efficiently.

function StockList({ stocks }) {
  return (
    <ul>
      {stocks.map((stock) => (
        <li key={stock.id}>{stock.symbol} — {stock.price}</li>
      ))}
    </ul>
  );
}

7. Forms (Controlled Components)

A "controlled" input ties its value directly to React state, so the component always knows the current input value instead of reading it from the DOM.

function LoginForm() {
  const [email, setEmail] = useState("");

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log(email);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={email} onChange={(e) => setEmail(e.target.value)} />
      <button type="submit">Submit</button>
    </form>
  );
}

📅 Day 2 — Hooks & Component Architecture

1. useEffect (Side Effects & Lifecycle)

useEffect runs code after render — for things like data fetching, subscriptions, or timers. The dependency array controls when it re-runs, and the returned function handles cleanup.

import { useEffect, useState } from "react";

function StockPrice({ symbol }) {
  const [price, setPrice] = useState(null);

  useEffect(() => {
    fetchPrice(symbol).then(setPrice);

    return () => {
      // cleanup (e.g. cancel subscription/interval)
    };
  }, [symbol]); // dependency array

  return <p>{symbol}: {price}</p>;
}

2. useContext (Avoiding Prop Drilling)

Context lets you share a value across many components without manually passing props down through every level — useful for themes, auth state, or app-wide settings.

const ThemeContext = createContext("light");

function App() {
  return (
    <ThemeContext.Provider value="dark">
      <Toolbar />
    </ThemeContext.Provider>
  );
}

function Toolbar() {
  const theme = useContext(ThemeContext);
  return <div className={theme}>Toolbar</div>;
}

3. useRef (DOM Access & Mutable Values)

useRef gives you a mutable container that persists across renders without causing a re-render when changed — commonly used to directly access a DOM element.

function FocusInput() {
  const inputRef = useRef(null);

  useEffect(() => {
    inputRef.current.focus();
  }, []);

  return <input ref={inputRef} />;
}

4. useReducer (Complex State Logic)

When state updates depend on more than a simple "set this value" — like multiple related fields or action-driven changes — useReducer centralizes that logic, similar to a switch-based state machine.

function reducer(state, action) {
  switch (action.type) {
    case "increment": return { count: state.count + 1 };
    case "decrement": return { count: state.count - 1 };
    default: return state;
  }
}

function Counter() {
  const [state, dispatch] = useReducer(reducer, { count: 0 });
  return (
    <button onClick={() => dispatch({ type: "increment" })}>
      {state.count}
    </button>
  );
}

5. Custom Hooks

A custom hook is just a function starting with "use" that wraps reusable stateful logic — letting you share behavior between components without repeating code.

function useStockData(symbol) {
  const [data, setData] = useState(null);

  useEffect(() => {
    let active = true;
    fetchStock(symbol).then((res) => { if (active) setData(res); });
    return () => { active = false; };
  }, [symbol]);

  return data;
}

// Usage
const data = useStockData("ONGC");

6. Performance: useMemo & useCallback

These hooks memoize expensive calculations or function references so they aren't recreated on every render — useful for optimizing large lists or avoiding unnecessary child re-renders.

const sortedStocks = useMemo(
  () => stocks.sort((a, b) => b.changePercent - a.changePercent),
  [stocks]
);

const handleSelect = useCallback(
  (id) => setSelectedId(id),
  []
);

7. Component Composition (children prop)

Instead of building rigid, configurable components, React favors composition — passing JSX as children so a wrapper component can render whatever is placed inside it.

function Card({ children }) {
  return <div className="card">{children}</div>;
}

// Usage
<Card>
  <h3>ONGC</h3>
  <p>-20% from entry</p>
</Card>

📅 Day 3 — React in Real-World Apps

1. React Router (Navigation)

React Router handles client-side navigation between "pages" in a single-page app, matching URL paths to the components that should render.

import { BrowserRouter, Routes, Route, Link } from "react-router-dom";

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/portfolio">Portfolio</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/portfolio" element={<Portfolio />} />
      </Routes>
    </BrowserRouter>
  );
}

2. Fetching APIs (Data Layer)

Combining useState and useEffect is the classic pattern for loading data from a backend — track the data, a loading flag, and fetch once on mount.

function usePortfolio() {
  const [stocks, setStocks] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch("/api/portfolio")
      .then((res) => res.json())
      .then((data) => { setStocks(data); setLoading(false); });
  }, []);

  return { stocks, loading };
}

3. Global State Management (Context vs Redux/Zustand)

For state shared across many unrelated components (like a logged-in user or a portfolio list), a dedicated store like Zustand or Redux is often simpler to scale than nested Context providers.

// Lightweight global state with Zustand
import { create } from "zustand";

const usePortfolioStore = create((set) => ({
  stocks: [],
  addStock: (stock) => set((state) => ({ stocks: [...state.stocks, stock] })),
}));

function PortfolioList() {
  const stocks = usePortfolioStore((s) => s.stocks);
  return <ul>{stocks.map((s) => <li key={s.id}>{s.symbol}</li>)}</ul>;
}

4. Error Boundaries & Loading States

An error boundary catches rendering errors in its child components and shows a fallback UI instead of crashing the whole app — React's equivalent of a try/catch for the component tree.

class ErrorBoundary extends React.Component {
  state = { hasError: false };
  static getDerivedStateFromError() { return { hasError: true }; }
  render() {
    if (this.state.hasError) return <p>Something went wrong.</p>;
    return this.props.children;
  }
}

function LoadingSpinner() {
  return <p>Loading...</p>;
}

5. Component Testing (React Testing Library)

React Testing Library encourages testing components the way a user interacts with them — querying rendered text and simulating clicks rather than testing internal implementation details.

import { render, screen, fireEvent } from "@testing-library/react";

test("counter increments on click", () => {
  render(<Counter />);
  fireEvent.click(screen.getByRole("button"));
  expect(screen.getByText("Count: 1")).toBeInTheDocument();
});

6. Next.js Integration (Server + Client Components)

Next.js's App Router splits components into Server Components (rendered on the server, can fetch data directly) and Client Components (marked with "use client", needed for interactivity like state and event handlers).

// Server Component (default in App Router)
async function PortfolioPage() {
  const stocks = await fetch("https://api.example.com/portfolio").then(r => r.json());
  return <PortfolioList stocks={stocks} />;
}

// Client Component (interactivity)
"use client";
function PortfolioList({ stocks }) {
  const [filter, setFilter] = useState("all");
  return (
    <div>
      <input onChange={(e) => setFilter(e.target.value)} />
      {/* render filtered stocks */}
    </div>
  );
}

7. Performance & Production Readiness

Code splitting defers loading parts of your app until they're needed, and React.memo skips re-rendering a component when its props haven't changed — both reduce wasted work in larger apps.

// Code splitting with lazy loading
const Dashboard = React.lazy(() => import("./Dashboard"));

function App() {
  return (
    <Suspense fallback={<LoadingSpinner />}>
      <Dashboard />
    </Suspense>
  );
}

// React.memo to avoid unnecessary re-renders
const StockRow = React.memo(({ stock }) => <tr><td>{stock.symbol}</td></tr>);
