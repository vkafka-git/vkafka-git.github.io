LINQ Joins, Grouping, and Aggregation Guide

Mental Map

🧠 Mental Map

Question: What is the logical order of operations when writing complex LINQ queries involving multiple tables and calculations?

  1. Join → Combine related collections (like Employees + Departments).
  2. GroupBy → Organize the combined data into buckets (e.g., by Department).
  3. Aggregate → Apply calculations inside each group (Sum, Average, Count).
  4. Select → Shape the final result into the form you want (e.g., Department + AverageSalary).

Shortcut mental model: Join → GroupBy → Aggregate → Select

Number of employees in each department - Inner Join Example

Question: How can we find the number of employees in each department using LINQ (Employees + Departments)?

What this does: Joins Employees with Departments, groups by department name, and counts how many employees are in each department.


var result = employees
    .Join(departments,
          e => e.DepartmentId,
          d => d.DepartmentId,
          (e, d) => new { e.Name, d.DepartmentName })
    .GroupBy(x => x.DepartmentName)
    .Select(g => new { Department = g.Key, Count = g.Count() });
Tip: LINQ Join is always an INNER JOIN by default.
Left Join Example

Question: How can we list all employees along with their department names, ensuring employees without a department are still included?

What this does: Ensures all employees are listed, even if they don’t belong to any department. Missing departments show as "No Department".


var leftJoin = employees
    .GroupJoin(departments,
        e => e.DepartmentId,
        d => d.DepartmentId,
        (e, deptGroup) => new { e, deptGroup })
    .SelectMany(
        x => x.deptGroup.DefaultIfEmpty(),
        (x, d) => new

            DepartmentName = d?.DepartmentName ?? "No Department"
        });
Tip: Use GroupJoin + DefaultIfEmpty() to simulate a LEFT JOIN in LINQ.

Three Table Join Example

Question: How can we calculate the average salary per department per location using Employees, Departments, and Locations tables?

What this does: Joins Employees → Departments → Locations, then groups by department and location, and calculates the average salary per group.


var avgSalaryPerDeptLocation = employees
    .Join(departments,
          e => e.DepartmentId,
          d => d.DepartmentId,
          (e, d) => new { e.Salary, d.DepartmentName, d.LocationId })
    .Join(locations,
          ed => ed.LocationId,
          l => l.LocationId,
          (ed, l) => new { ed.Salary, ed.DepartmentName, l.LocationName })
    .GroupBy(x => new { x.DepartmentName, x.LocationName })
    .Select(g => new
    {
        Department = g.Key.DepartmentName,
        Location = g.Key.LocationName,
        AverageSalary = g.Average(x => x.Salary)
    });
Tip: For multiple tables, chain multiple Join calls before grouping and aggregating.
Method Syntax vs Query Syntax

Question: How can the same join between Employees and Departments be written in both LINQ method syntax and query syntax?

What this shows: The same join written in two styles — method syntax (fluent chaining) and query syntax (SQL-like). Both produce identical results.


// Method Syntax
var result = employees.Join(departments,
    e => e.DepartmentId,
    d => d.DepartmentId,
    (e, d) => new { e.Name, d.DepartmentName });

// Query Syntax
var result = from e in employees
             join d in departments
             on e.DepartmentId equals d.DepartmentId
             select new { e.Name, d.DepartmentName };
Tip: Both styles compile to the same thing. Method syntax is more common in production code, while query syntax feels closer to SQL.
5th Highest Salary Example

Question: How can we find the 5th highest salary of any employee using LINQ with method syntax?

What this does: Orders the employees by salary in descending order, skips the top 4, and selects the next one — which is the 5th highest salary.


var fifthHighestSalary = employees
    .OrderByDescending(e => e.Salary)   // sort salaries high → low
    .Select(e => e.Salary)              // project salary only
    .Distinct()                         // remove duplicates
    .Skip(4)                            // skip top 4 salaries
    .FirstOrDefault();                  // take the 5th highest

Console.WriteLine($"5th Highest Salary: {fifthHighestSalary}");
Tip: Use Skip(N-1) with FirstOrDefault() to get the Nth highest salary. Add Distinct() if you want to ignore duplicate salaries.

Nth Highest Salary Example

Question: How can we find the Nth highest salary (e.g., 5th highest) using LINQ?

Employees Without Department Example

Question: How can we list employees who do not belong to any department?

What this does: Performs a LEFT JOIN between Employees and Departments, then filters where department is null.


var employeesWithoutDept = from e in employees
                           join d in departments
                           on e.DepartmentId equals d.DepartmentId into deptGroup
                           from d in deptGroup.DefaultIfEmpty()
                           where d == null
                           select e;

foreach (var emp in employeesWithoutDept)
{
    Console.WriteLine(emp.Name);
}
Tip: Use DefaultIfEmpty() to simulate LEFT JOIN and check for nulls.
Find Duplicates in a List Example

Question: How can we find duplicate elements in a list using LINQ?

What this does: Groups elements by value and selects those with count greater than 1.


var numbers = new List { 1, 2, 3, 2, 4, 5, 1 };

var duplicates = numbers
    .GroupBy(n => n)
    .Where(g => g.Count() > 1)
    .Select(g => g.Key);

foreach (var dup in duplicates)
{
    Console.WriteLine($"Duplicate: {dup}");
}
Tip: GroupBy() + Count() is the easiest way to detect duplicates.

Global Exception Handling Middleware

Question: How can we implement a simple global exception handling middleware in ASP.NET Core?


public class ExceptionHandlingMiddleware
{
    private readonly RequestDelegate _next;

    public ExceptionHandlingMiddleware(RequestDelegate next)
    {
        _next = next;
    }

    public async Task Invoke(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            context.Response.StatusCode = 500;
            await context.Response.WriteAsync($"Error: {ex.Message}");
        }
    }
}

// Register in Program.cs
app.UseMiddleware<ExceptionHandlingMiddleware>();
Tip: This middleware catches unhandled exceptions and returns a 500 response.

{

Repository Pattern with Dependency Injection (GetAll)

Question: How can we implement a simple repository with DI that only exposes GetAll()?


// Entity
public class Employee
{
    public int EmployeeId { get; set; }
    public string Name { get; set; }
}

// Repository interface
public interface IEmployeeRepository
{
    IEnumerable<Employee> GetAll();
}

// Repository implementation
public class EmployeeRepository : IEmployeeRepository
{
    private readonly List<Employee> _employees = new()
    {
        new Employee { EmployeeId = 1, Name = "Alice" },
        new Employee { EmployeeId = 2, Name = "Bob" }
    };

    public IEnumerable<Employee> GetAll() => _employees;
}

// Service using repository
public class EmployeeService
{
    private readonly IEmployeeRepository _repository;

    public EmployeeService(IEmployeeRepository repository)
    {
        _repository = repository;
    }

    public IEnumerable<Employee> GetEmployees() => _repository.GetAll();
}

// Register in Program.cs
builder.Services.AddScoped<IEmployeeRepository, EmployeeRepository>();
builder.Services.AddScoped<EmployeeService>();

// Usage in Controller
public class HomeController : Controller
{
    private readonly EmployeeService _service;

    public HomeController(EmployeeService service)
    {
        _service = service;
    }

    public IActionResult Index()
    {
        var employees = _service.GetEmployees();
        return Ok(employees);
    }
}

Expected Output:

[{"EmployeeId":1,"Name":"Alice"},{"EmployeeId":2,"Name":"Bob"}]
Tip: Keep repositories minimal — exposing only GetAll() here makes it easy to demonstrate DI without extra complexity.
Async/Await with HttpClient

Question: How can we use async/await with HttpClient to fetch data without blocking threads?


using System;
using System.Net.Http;
using System.Threading.Tasks;

public class Program
{
    private static readonly HttpClient _httpClient = new HttpClient();

    public static async Task Main(string[] args)
    {
        string url = "https://jsonplaceholder.typicode.com/posts/1";

        // Async call with await
        string result = await FetchDataAsync(url);

        Console.WriteLine("Response:");
        Console.WriteLine(result);
    }

    public static async Task<string> FetchDataAsync(string url)
    {
        HttpResponseMessage response = await _httpClient.GetAsync(url);

        response.EnsureSuccessStatusCode(); // throws if not 2xx

        string content = await response.Content.ReadAsStringAsync();
        return content;
    }
}

Expected Output:

Response: { "userId": 1, "id": 1, "title": "sunt aut facere repellat provident occaecati...", "body": "quia et suscipit..." }
Tip: await frees the thread while waiting for the HTTP response, improving scalability in web apps.
Generic Class Example (UtilityName)

Question: How can we create a generic utility class that works with any type?


// Generic utility class
public class DataStore<T>
{
    private readonly List<T> _items = new();

    public void Add(T item)
    {
        _items.Add(item);
    }

    public IEnumerable<T> GetAll()
    {
        return _items;
    }
}

// Usage
var intStore = new DataStore<int>();
intStore.Add(10);
intStore.Add(20);

var stringStore = new DataStore<string>();
stringStore.Add("Alice");
stringStore.Add("Bob");

Console.WriteLine(string.Join(", ", intStore.GetAll()));    // 10, 20
Console.WriteLine(string.Join(", ", stringStore.GetAll())); // Alice, Bob

Expected Output:

10, 20 Alice, Bob
Tip: Naming it DataStore<T> makes it clear this is a reusable container, not tied to persistence or repositories.

Extension Methods Example

Question: How can we create and use an extension method to add functionality to an existing type?


// Extension method must be in a static class
public static class StringExtensions
{
    // Another example: capitalize first letter
    public static string CapitalizeFirst(this string value)
    {
        return char.ToUpper(value[0]) + value.Substring(1);
    }
}

// Usage
class Program
{
    static void Main()
    {
        string name = "alice";
        Console.WriteLine(name.CapitalizeFirst()); // Alice
    }

Alice
Tip: Extension methods let you "extend" existing types (like string) with new methods, while keeping your code clean and reusable.
